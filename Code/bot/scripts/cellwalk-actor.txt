# Walks out of range and back, announcing the way back the way a player walking between outdoor cells does.
#
#   powershell -ExecutionPolicy Bypass -File Tools\VR\run-bot-tests.ps1 -Pair cellwalk
#
# A client tells the server it changed cell three ways, and each must send the arriving player what is around them.
# DiscoveryService::VisitExteriorCell raises the exterior-enter whenever the grid square the player stands in changes, and the grid shift only when the *centre* of the loaded block moves.
# That centre trails the player: it moves by one cell once the player is two cells from it.
# So walking from one outdoor cell into the next sends the exterior-enter alone, and the loaded cells do not move.
# The server ranges a player by that centre; the exterior-enter alone leaves it where it was.
#
# The bot sent both messages, centred where it stood, so this walk could not be reproduced.
# `gridshift lag` makes the bot walk like the game: an entry for each cell, a shift trailing one cell behind.

log cellwalk actor
waitfor connected 45
collect spawn ownership
record cellwalk actor

waitfor players >= 1 30
expect known me

log settling where the other player can see me
wait 8
waitfor known other 40
expect known other

# Out of the other bot's range, announced normally. The server stops sending each of us to the other, and the
# copy the far side holds is dropped -- this is the same journey the range pair makes.
log walking five cells east, announcing normally
walk rel 20000 0 3000
wait 12
expect connected

# Everything counted from here is a re-send, not a leftover from joining. Without this the check below is
# already satisfied before the walk begins -- the first version of this pair counted seven spawns from the join
# and passed against a server with the fix taken out, which is exactly the bug it was written to catch.
log counting only what arrives from here
reset spawns

log coming back the way the game walks, the centre trailing
gridshift lag
walk rel -20000 0 3000
wait 6

# The assertion. Back in range, the server owes this bot the other player again.
# The count is of re-sends only, so one is enough.
log the other player should have been sent to me again
waitfor spawns other >= 1 25
expect spawns other >= 1
expect known other
expect actors == 2
expect connected

gridshift on
record off
report bot-cellwalk-actor.txt
log done
stop

# An NPC dead in this game stays dead when another game, its owner, has it alive, and the owner is told to kill it.
#
#   python Tools\VR\live-check.py live-dead-stays-dead
#   python Tools\VR\live-check.py --expect-fail live-dead-stays-dead     on a build without the fix: must be RED
#
# Two games' saves can disagree on who is dead: a death behind a stand-in, or one while the other game was away.
# After a reconnect the owner's living one won: this game stood its body up again, a dead soldier walking, a different
# one in each game.
# The bandit 45A3F outside Mistwatch is dead in the test save. Offline (F6), this game leaves the server (the bot takes
# no hand-overs), and the bot, leading, registers the bandit alive. Back online, this game's body meets the owner's
# living bandit: it must stay a body, and the bot must get the killing blow for it.
# A run counts only when (REQUIRE) the bandit was dead here before the game went back online, and the bot did lead.
party lead
log live dead stays dead
waitfor connected 45
expect known me
waitfor known other 40
wait 3
stay
log REQUIRE ref 45A3F dead

log -- offline (F6); the bot registers the bandit alive meanwhile
log DO f6
wait 8
npc 45A3F
waitfor owned == 1 20
wait 2

log -- back online, as a member: this game's body meets the bot's living bandit
log DO f6
wait 15
waitfor known other 60
wait 10
# "info] " is in the bot's own log line, not in its echo of this check.
log REQUIRE bot logged info\] Leading the party
log CHECK ref 45A3F dead
log CHECK logged DeathWins: 45A3F
log CHECK bot logged Health change of our [0-9A-F]+ by player \d+: -100000
log CHECK game alive
wait 2
log done
stop

# Loading a save while connected: twice in a row, and once more after dying and coming back.
#
#   python Tools\VR\live-check.py live-load
#
# A load after death crashed: a save/load request built while connected, the Loading Menu up, and an access violation 68 ms later.
# `log DO load last` loads the most recent save through DevBench at a chosen moment.
# This bot stands by throughout, so there is a copy to tear down each time.
# The load in the middle of dying is its own script (live-load-dead), because that one takes the game down in the no-headset rig.
log live load
waitfor connected 45
collect spawn
expect known me
waitfor known other 40
wait 6
log CHECK game inworld
wait 3

log -- loading the last save while connected
log DO load last
wait 45
log CHECK game inworld
log CHECK player alive
wait 3

log -- and again
log DO load last
wait 45
log CHECK game inworld
log CHECK player alive
wait 3

log -- killed alone (this bot leaves the party, so nobody waits for a revive), brought back by the mod, then a load
party leave
wait 3
log DO console player.kill
wait 14
log CHECK player alive
wait 2
log DO load last
wait 45
log CHECK game inworld
log CHECK player alive
wait 3

# The last save can lie anywhere, in another worldspace too (FUS Testing's is in Whiterun), where the next script's bot finds no host.
log -- back to the rig's start
log DO papyrus ObjectReference MoveTo 14 4AFD9 f:-32 f:-911 f:262 b:false
wait 30
log CHECK game alive

log done
stop
